# نيل — نموذج محاكاة ويب تفاعلي

هذا المشروع **محاكاة معملية** لمنصة «نيل» المقترحة، وليست منتجًا إنتاجيًا ولا نظام تبرعات ولا خدمة ذكاء اصطناعي متصلة بخادم. كل الجمعيات والجهات والمشاريع والأرقام والرسائل والنتائج في النموذج **افتراضية**، وتُحفظ التغييرات على متصفح الجهاز نفسه فقط.

**الرابط المباشر:** https://aboodalsharabi.github.io/neel-web-demo/
**المستودع:** https://github.com/AboodAlsharabi/neel-web-demo

## الفكرة

تساعد «نيل» الجمعية على نشر مشروعها الشبابي وتحديد ما تحتاجه كاحتياجات مستقلة (تدريب، أجهزة، تكاليف تشغيل، فرص تدريب عملي، خبرة، خدمات)، وتساعد الجهة الداعمة على اكتشاف المشاريع المناسبة وتقديم مساهمة تجريبية ومتابعة الطلب والاتفاق من لوحة واحدة. لا يُرجع النموذج تمويلًا مضمونًا، ولا يمثل وجود شراكة حقيقية، ولا يدعي أن ميزاته غير موجودة لدى أي منافس.

## ما يعمل فعليًا في هذا النموذج

- صفحة تعريفية واحدة `index.html` وصفحة اختيار الدور `demo.html`.
- لوحتا تحكم: `app.html#/association/...` و`app.html#/supporter/...`.
- بيانات أولية مترابطة بين الدورين، وحفظ محلي فوري في `localStorage`.
- إنشاء مشروع واحتياجات، ثم حفظ مسودة أو نشر تجريبي.
- مساعد نيل التجريبي: تحليل وصف المشروع، اقتراح احتياجات قابلة للرفض أو الاعتماد، اقتراح شركاء مع الأسباب، وإعداد مسودة رسالة.
- طلبات تعاون بحالات: مسودة، أُرسل، قيد المراجعة، مهتم، اجتماع، موافقة مبدئية، اعتذار، مغلق.
- تسجيل مساهمة جزئية أو كاملة، واستبعاد العروض غير المؤكدة من التغطية حتى تؤكدها الجمعية.
- تغطية الاحتياج مشتقة من المساهمات المؤكدة والطلبات النشطة، وليست حقلًا يُملأ يدويًا.
- تبديل الدور دون فقد التغييرات، وجولة إرشادية لكل دور.
- نتائج شباب تجريبية تفرق بين المستهدف والنتيجة المسجلة ومصدرها، واستبيان قصير غير معرّف.
- حماية عرض الدور: فتح مسار يخص الدور الآخر يعرض حارسًا مع إجراء تبديل صريح.
- زر «إعادة ضبط التجربة» مع نافذة تأكيد يعيد البيانات الأولية.

## ما هو محاكاة

- الذكاء الاصطناعي: قواعد محلية ثابتة داخل `assets/js/services/ai-agent-mock.js`. لا يوجد اتصال بنموذج لغوي أو مفتاح API.
- المراسلات: رسائل تجريبية تُحفظ محليًا فقط. لا يُرسل بريد أو واتساب أو SMS.
- المساهمات المالية: أي دعم مالي يظهر كتعهد وصفي فقط. لا توجد تبرعات ولا مدفوعات ولا إيصالات.
- الأدوار: اختيار «جمعية» أو «جهة داعمة» ليس مصادقة حقيقية ولا نظام صلاحيات أمني.
- الحفظ: `localStorage` ليس قاعدة بيانات، ولا يوجد تزامن بين الأجهزة أو المستخدمين.
- النتائج والمؤشرات: أرقام تجريبية موسومة بوضوح، ولا تُدعى نتائج أثر حقيقية.

## ما يحتاج خادمًا لاحقًا

- حسابات حقيقية ومصادقة وصلاحيات.
- إرسال بريد أو رسائل فعلية.
- تكامل ذكاء اصطناعي حقيقي بمراجعة بشرية.
- المدفوعات والتبرعات والاتفاقيات الرسمية.
- تزامن مركزي وإشعارات خارجية وسجلات تدقيق.

## التقنيات والهيكل

HTML5 + CSS3 + JavaScript أصلي بوحدات ES Modules. لا توجد تبعيات تشغيل خارجية، ولا React أو إطار SPA، ولا مكتبات CDN إلزامية. الأيقونات SVG مضمنة، والرسوم مبنية بـ CSS/SVG، والخطوط تستخدم خطوط النظام العربية.

```text
index.html             الصفحة التعريفية
demo.html              اختيار الدور التجريبي
app.html               م shell لوحتي التحكم مع hash routing
404.html               صفحة غير موجودة
server.mjs             خادم محلي بسيط بأنواع MIME صحيحة
assets/css/            tokens / global / landing / dashboard / views / responsive
assets/js/             main / router / store / seed-data / utils / services / components / views
docs/DEMO_SCRIPT.md    سيناريو العرض
docs/DATA_MODEL.md     نموذج البيانات والحالات
```

## التشغيل محليًا

يتطلب المشروع خادمًا ثابتًا لأن وحدات ES لا تعمل عبر `file://`.

```bash
node server.mjs
```

ثم افتح:

```text
http://127.0.0.1:5500
```

يمكن تغيير المنفذ عبر `PORT=5501 node server.mjs`.

أمر فحص بناء الجملة:

```bash
$files = Get-ChildItem -Path assets/js -Recurse -Filter *.js
foreach ($file in $files) { node --check $file.FullName }
```

## بيانات الدورين الافتراضية

- الجمعية: `ORG-001` «جمعية مهارات الغد» — الرياض.
- الجهة الداعمة: `SUP-002` «شركة مدى التقنية» — شركة تقنية تدعم الأجهزة والخدمات في العرض الأولي.
- المشروع المحوري: `PROJ-001` «تأهيل 100 شاب وشابة للمهارات الرقمية».
- احتياج الأجهزة: `NEED-102` مطلوب 20 جهازًا.
- الطلب الأول: `REQ-101` موجه من الجمعية إلى الجهة الداعمة لحالة «قيد المراجعة».

غيّر الدور من `الإعدادات ← تبديل الدور` أو من الأعلى. يبقى نفس المخزن المحلي، لذلك تظهر تحديثات أحد الطرفين للطرف الآخر.

## الحفظ المحلي وإعادة الضبط

المفاتيح المستخدمة:

- `neel-demo-v1:state`: كل بيانات المحاكاة.
- `neel-demo-v1:session`: الدور الحالي.
- `neel-demo-v1:flash`: رسالة عابرة بين عمليات التنقل.
- `neel-demo-v1:tour:<role>`: حالة الجولة لكل دور.
- `neel-agent-rejected:<projectId>`: رفض اقتراحات المساعد لكل مشروع.

لا يُرفع أي شيء إلى خادم. لإعادة الحالة الأولى: `الإعدادات ← إعادة ضبط التجربة ← نعم، أعد الضبط`.

## النشر على GitHub Pages

المشروع منشور حاليًا على https://aboodalsharabi.github.io/neel-web-demo/ (فرع `main`، مجلد الجذر). لإعادة إعداد النشر أو نشر نسخة أخرى:

1. ارفع محتويات المشروع إلى مستودع (بدون تجاهل `assets` و`docs`).
2. في المستودع: `Settings → Pages`.
3. اختر فرع النشر ومجلد `/ (root)` (أو `/docs` إذا خططت لنشر من هناك، لكن المسارات الحالية مصممة للجذر).
4. تأكد أن `index.html` موجود في جذر المصدر المنشور.
5. افتح الرابط مثل `https://username.github.io/neel-web-demo/`، ثم جرّب رابطًا داخليًا مباشرًا مثل `https://username.github.io/neel-web-demo/app.html#/association/projects/PROJ-001`.
6. لا حاجة لإعادة توجيه الخادم لأن التنقل يستخدم `#` داخل `app.html`.

بما أن النشر تحت مجلد فرعي (`/neel-web-demo/`) وليس جذر النطاق، لا يجوز استخدام مسارات مطلقة تبدأ بـ `/`؛ كل المسارات في المشروع نسبية أو عبر `#`، وقد تُختبر المسارات الـ29 على النسخة المنشورة دون أخطاء في الكونسول.

## التبعيات الخارجية

لا توجد تبعيات خارجية وقت التشغيل ولا مفاتيح API. الأدوات المستخدمة للتطوير والفحص محلية فقط (Node.js للفحص/الخادم وChrome للاختبار) وليست مطلوبة لتشغيل الموقع بعد النشر.

## حدود متبقية

- لا يوجد backend ولا مصادقة حقيقية.
- لا توجد رسائل خارجية ولا AI متصل.
- لا توجد مدفوعات أو تبرعات.
- لا توجد نسخة احتياطية ولا تصدير PDF ولا تعدد لغات في هذه النسخة.
